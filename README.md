# Behavioral Detection Pipeline for Windows Host Telemetry

Ingest Windows Sysmon/Security event logs, build per-process behavioral
features, detect attacker behavior with (a) hand-written Sigma-style rules and
(b) an unsupervised anomaly model, map alerts to MITRE ATT&CK, and evaluate
against Chainsaw/Hayabusa as a rules-only baseline — reporting precision,
recall, and false-positive volume.

> Design brief and working rules: [`CLAUDE.md`](CLAUDE.md). Design decisions:
> [`docs/design.md`](docs/design.md). Which Sigma features the rule engine
> supports: [`docs/sigma-support.md`](docs/sigma-support.md). From a real
> vulnerability to detections:
> [`docs/from-vulnerability-to-detection.md`](docs/from-vulnerability-to-detection.md).

## Research questions

1. How much attack behavior does a pure rules approach (Sigma via
   Chainsaw/Hayabusa) miss, per ATT&CK technique?
2. Does a behavioral anomaly model catch some of the misses, and at what
   false-positive cost?
3. Does combining both (rules OR model) beat either alone at a fixed alert
   budget?

## Pipeline

```
raw .evtx -> ingest -> normalize -> features -> (rules | model)
          -> alerts + ATT&CK mapping -> evaluate (vs. Chainsaw/Hayabusa)
```

## Reproduce

```bash
make setup      # create venv, install package with dev extras
make test       # run the test suite (incl. the no-leakage split check)
```

Then run the pipeline per stage (each writes a Parquet the next one reads):

```bash
make ingest    EVTX=data/lab/raw/sample.evtx  OUT=data/lab/raw/sample.parquet
make normalize IN=data/lab/raw/sample.parquet OUT=data/lab/normalized/sample.parquet
# attach labels from the run log (time-window rule, docs/lab-setup.md s5):
make label     IN=data/lab/normalized/sample.parquet LABELS=data/lab/labels.csv \
               OUT=data/lab/normalized/labeled.parquet SRC=lab
# evaluate rules + model and regenerate every table and the figure:
make evaluate  EVENTS=data/lab/normalized/labeled.parquet   # -> artifacts/
# optionally fold in the external SigmaHQ baseline (Chainsaw/Hayabusa output):
make evaluate  EVENTS=data/lab/normalized/labeled.parquet EXTERNAL=hunt.json ETOOL=chainsaw
```

`make evaluate` writes `artifacts/summary.csv`, `artifacts/results.md`,
`artifacts/per_technique_recall.csv` and `.png`. The **Results** table above is
filled from `artifacts/summary.csv` — it stays `TODO` until the pipeline is run
on real data (no number is hand-written). `make help` lists every target.

Dependency versions are floored in `pyproject.toml` and the exact installed set
is frozen in `requirements.lock` (`make lock`) for byte-for-byte reproducible
runs — install those pinned versions with `pip install -r requirements.lock`.

Data is **not** committed. See [`data/README.md`](data/README.md) to obtain the
lab and public datasets.
