# Behavioral Detection Pipeline for Windows Host Telemetry

Ingest Windows Sysmon/Security event logs, build per-process behavioral
features, detect attacker behavior with (a) hand-written Sigma-style rules and
(b) an unsupervised anomaly model, map alerts to MITRE ATT&CK, and evaluate
against Chainsaw/Hayabusa as a rules-only baseline — reporting precision,
recall, and false-positive volume.

> Design brief and working rules: [`CLAUDE.md`](CLAUDE.md).

## Research questions

1. How much attack behavior does a pure rules approach (Sigma via
   Chainsaw/Hayabusa) miss, per ATT&CK technique?
2. Does a behavioral anomaly model catch some of the misses, and at what
   false-positive cost?
3. Does combining both (rules OR model) beat either alone at a fixed alert
   budget?

## Pipeline

```
raw .evtx -> ingest -> normalize -> features -> (rules | model)
          -> alerts + ATT&CK mapping -> evaluate (vs. Chainsaw/Hayabusa)
```
